# Prioritization and trade-offs

## Start with strategy

Difficulty prioritizing usually means the strategy is unclear, not that a framework is missing. If the user cannot say what the company is optimizing for now, help them get that from whoever owns it. Asking for the goal fixes the cause. Asking the boss to rank the list only fixes it once.

Frameworks organize judgment. The scores are still human choices, and "data-driven" can be used to justify a decision already made. Cross-check sources and treat conflicts as a reason for doubt.

## Evaluate an opportunity

1. **Value:** strategic, business and user value. Strategic bets are the hardest to quantify; say so.
2. **Resources:** people, time, and the cost of changing course (re-aligning people is a cost).
3. **Trade-off:** why now, and what gets pushed out.

Prioritize problems tied to the agreed goal, not individual signals that arrive loudly. For each new request ask: what problem does it serve, and is that in the current goal? If not, park it for re-planning. If yes, it still has to beat what it displaces plus the cost of switching.

Judge value before effort. Easy work that does not close the gap is still waste.

## Tools

- **Kano:** Basic (absence angers, presence is expected), Performance (more is better), Delighter (unexpected). Fix broken basics first. Beyond "good enough", extra investment in a basic earns little. Delighters decay into basics over time. Frequency of use does not equal opportunity.
- **RICE:** only when reach, impact, confidence and effort can honestly be compared. Mark estimates.
- **MoSCoW:** for trimming an already committed scope.
- **Value vs effort:** quick wins and major bets. Check data complexity (see CDM/ORD) before calling anything quick.

State which assumption, if wrong, would reverse the ranking.

## When capacity is full

Scope, speed, quality and resources trade against each other. The healthy moves are to cut scope, accept a stated quality trade-off, extend time, or add capacity, chosen openly with the decision maker. Silent overtime, silent delay and silent technical debt hide the price, so the same overload returns.

## Disagreeing with a top-down decision

1. Ask what triggered it. They may know something the PM does not.
2. Bring the evidence they lack.
3. Show the trade-off: doing X means Y and Z move.
4. Let them decide. If overruled, state the disagreement once and commit.

Step 4 never replaces steps 2 and 3. A note recorded only to avoid blame is not pushing back. Acknowledge political risk honestly and help the user phrase it in a way that keeps the relationship.
